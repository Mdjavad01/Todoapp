# چک‌لیست تست دستی APK — پشتیبان‌گیری و بازیابی (P1.3)

> تست خودکار روی گوشی ممکن نیست؛ این چک‌لیست باید **یک‌بار روی دستگاه واقعی اندروید**
> پس از نصب APK جدید (نسخه‌ی حاوی P1.3) اجرا شود. هر گام که تأیید شد تیک بخورد؛
> هر موردی که شکست خورد، با شماره‌ی گام و رفتار مشاهده‌شده گزارش شود.

## پیش‌زمینه

- APK نسخه‌ی ≥ 1.0.9 (بعد از P1.3) — نسخه اپ ۴.۴.۰
- یک حساب تلگرام (یا بله) در دسترس روی همان گوشی + فایل‌منیجر (Files/My Files)
- داده‌ی آزمایشی: قبل از شروع، ۲ لیست + چند کار + یک زیرکار + یک یادآور بسازید

## بخش الف — ذخیره‌ی نسخه‌ی پشتیبان (منوی اشتراک)

- [ ] **الف۱.** تنظیمات ← پشتیبان‌گیری و بازیابی ← بلوک «۱. ذخیره‌ی نسخه‌ی پشتیبان» ← دکمه‌ی «ذخیره‌ی نسخه‌ی پشتیبان» → **منوی اشتراک سیستم باید باز شود** (نه هیچ‌ اتفاقی نیفتد و نه پیام «دانلود شد» بدهید)
- [ ] **الف۲.** در منوی بازشده «ذخیره در فایل‌ها» (Save to Files / Files توسط Download یا فایل‌منیجر) را انتخاب کنید → توست باید نام فایل (`karam-backup-....json`) و تعداد رکورد بگوید: «فایل … با N رکورد ذخیره شد»
- [ ] **الف۳.** فایل ذخیره‌شده را در فایل‌منیجر باز کنید (لمس ساده) → باید JSON خوانا باشد و `app: "karam"` و `kind: "backup"` دیده شود
- [ ] **الف۴.** دوباره «ذخیره‌ی نسخه‌ی پشتیبان» را بزنید و این‌بار مقصد را **تلگرام ← ذخیره‌شده‌ها (Saved Messages)** بگذارید → فایل در تلگرام تحویل شود
- [ ] **الف۵.** دوباره ذخیره و این‌بار **بدون انتخاب مقصد، Back بزنید** (انصراف از شیت اشتراک) → توست باید «ذخیره نشد — مقصدی انتخاب نشد…» باشد؛ **هیچ‌وقت** «ذخیره شد» نباید دیده شود
- [ ] **الف۶.** بعد از هر ذخیره‌ی موفق، زیر عنوان کارت باید «آخرین پشتیبان: <تاریخ شمسی امروز>» ظاهر/به‌روز شود؛ بعد از انصراف، نباید تغییر کند
- [ ] **الف۷.** آیکن «؟» بلوک ۱ → پاپ‌اوور باید بگوید فایل چه چیزی دارد و کجا می‌رود (بدون وعده‌ی اشتباه)
- [ ] **الف۸.** (حساب‌دار) تنظیمات ← حساب و داده‌های من ← «دریافت داده‌های من (JSON)» → همان منوی اشتراک باز شود و فایل `karam-data-....json` قابل ذخیره باشد

## بخش ب — بازیابی روی نصب تازه

- [ ] **ب۱.** کارام را حذف نصب کنید و دوباره نصب کنید (داده‌ی صفر — لیست «کارهای من» خالی)
- [ ] **ب۲.** فایل پشتیبان را از تلگرام (ذخیره‌شده‌ها) یا فایل‌منیجر دانلود/دریافت کنید
- [ ] **ب۳.** تنظیمات ← بلوک «۲. بازیابی از فایل» ← «انتخاب فایل پشتیبان» → انتخاب‌گر باید **فایل را نشان دهد و قابل انتخاب باشد** (فیلتر accept نباید مانع شود)
- [ ] **ب۴.** بعد از انتخاب: **دیالوگ پیش‌نمایش/تأیید** باید باز شود — نام فایل، تاریخ ساخت شمسی، شمارش لیست/کار/زیرکار/یادآور و جمله‌ی «هیچ‌چیز حذف نمی‌شود»
- [ ] **ب۵.** «انصراف» → هیچ داده‌ای اضافه نشود (شمارش اپ تغییری نکند)
- [ ] **ب۶.** دوباره انتخاب فایل ← «بازیابی» → **دیالوگ نتیجه‌ی ماندگار** با سه عدد (افزوده/به‌روز شده/محلی جدیدتر ماند) بماند تا خودتان ببندید
- [ ] **ب۷.** بعد از بستن: لیست‌ها/کارها/زیرکار/یادآور قبلی برگشته باشند و یادآورها در صفحه‌ی جزئیات فعال باشند
- [ ] **ب۸.** آیکن «؟» بلوک ۲ → پاپ‌اوور باید ادغام LWW و «حذف نمی‌شود» را توضیح دهد

## بخش ج — خطاها و موارد خاص

- [ ] **ج۱.** یک فایل JSON غیرکارام (مثلاً خروجی هر اپ دیگری) را بازیابی کنید → توست «فایل پشتیبان کارام نیست»
- [ ] **ج۲.** یک فایل خراب (نصفه/دستکاری‌شده) → توست «فایل خراب است…»
- [ ] **ج۳.** در فایل پشتیبان سالم `version` را به `99` تغییر دهید → توست «این فایل از نسخه‌ی جدیدتر کارام است؛ اول اپ را به‌روزرسانی کنید»
- [ ] **ج۴.** بازیابی دوباره روی همان داده (بدون تغییر) → همه‌ی موارد باید در ستون «محلی جدیدتر ماند» یا «به‌روز شد» بشمارند؛ هیچ رکورد تکراری ساخته نشود

## بخش د — رگرسیون

- [ ] **د۱.** درگاه پرداخت زیبال (حساب‌دار) همچنان باز می‌شود (پلاگین‌های Share/Filesystem نباید بیلد را خراب کرده باشند)
- [ ] **د۲.** یادآورها زنگ می‌زنند (تست با کار آزمایشی ۲ دقیقه بعد)
- [ ] **د۳.** ورود با تلگرام/ایمیل و سینک ابری سالم
- [ ] **د۴.** قفل بیومتریک (اگر روشن است) باز می‌شود

## نکات شناخته‌شده (در گزارش P1.3 ثبت شده)

- تشخیص «انصراف» فقط برای مسیر بستن ساده‌ی شیت اشتراک قطعی است (RESULT_CANCELED). اگر کاربر مقصدی را انتخاب کند و **درون همان اپ مقصد** ارسال را لغو کند، اپ آن را «ذخیره شد» می‌بیند (فایل نوشته شده و تحویل اپ مقصد شده — قابل تشخیص نیست). این محدودیت پلاگین Share است.
- «ذخیره در فایل‌ها» بسته به برند گوشی (سامسونگ/شیائومی/…) نام‌های متفاوتی دارد؛ گام الف۲ با هر مسیری که فایل را در حافظه بگذارد تأیید شود.
