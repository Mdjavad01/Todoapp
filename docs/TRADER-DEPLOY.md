# راهنمای انتشار فاز تریدر (چک‌لیست تریدر)

> این فایل دستورالعمل دقیق انتشار قابلیت «چک‌لیست تریدر» است — تغییری که به دیتابیس سرور ستون اضافه می‌کند.
> **ترتیب مهم است؛ برعکس‌کردنش باعث از‌دست‌رفتن داده می‌شود** (توضیح در «چرا ترتیب؟» پایین).

## چه چیزهایی تغییر می‌کند؟

| ستون نو | جدول | نوع | معنی |
| --- | --- | --- | --- |
| `item_type` | tasks | VARCHAR(16) NULL | نوع آیتم چک‌لیست: `check`/`num`/`note`/`choice`/`score` — NULL = تیک ساده |
| `item_value` | tasks | VARCHAR(255) NULL | مقدار آیتم (عدد/انتخاب/امتیاز؛ یادداشت کوتاه هم همین‌جاست) |
| `pinned` | lists | TINYINT(1) NOT NULL DEFAULT 0 | لیست پین‌شده — همیشه بالای فهرست |

فایل‌های مرتبط: `deploy/upgrade-v1.9.1.sql` (مهاجرت تکرارپذیر MySQL) · `deploy/install.sql` و `deploy/install.sqlite.sql` (نصب نو — از قبل به‌روز) · `backend/src/Support/TaskSchema.php` (مهاجرت خودکار زمان‌اجرای SQLite/MySQL برای نصب‌های محلی).

## ترتیب انتشار (۳ گام)

1. **اول دیتابیس هاست** — فول‌بک کامل بگیر (بخش ۱۸ INSTALL) و بعد SQL را اجرا کن:
   ```bash
   # از ssh یا phpMyAdmin:
   mysql -u <USER> -p <DBNAME> < deploy/upgrade-v1.9.1.sql
   # در phpMyAdmin: فایل deploy/upgrade-v1.9.1.sql را در تب SQL ایمپورت کن
   ```
   مهاجرت **تکرارپذیر** است — چند بار اجرا بی‌ضرر (هر دستور با گارد INFORMATION_SCHEMA).
2. **بعد بک‌اند** — پوشه‌های `api/` (و `panel/`) جدید را روی هاست آپلود کن (مطابق بخش ۲ INSTALL).
3. **آخر APK** — APK جدید (versionCode دست‌نخورده از این شاخه، بیلد بازار `bun run build:www:bazaar` + cap sync) را بساز و در بازار بگذار.

### چرا این ترتیب؟ (گزارش ممیزی مرحله ۰)

سرور قدیمی فیلدهای ناشناخته را در `normalizeTask/normalizeList` **بی‌صدا نادیده می‌گیرد**. اگر APKِ جدید (که `itemType`/`itemValue`/`pinned` می‌فرستد) قبل از مهاجرت سینک کند:
push مقدار → سرور حذفش می‌کند و `rev` بالا می‌رود → pull رکورد بدون فیلد برمی‌گرداند → کلاینت کل ردیف محلی را جایگزین می‌کند → **مقدار حتی روی خود دستگاه هم پاک می‌شود**.
با ترتیب بالا هیچ بازه‌ی خطرناکی وجود ندارد: APK قدیمی هرگز کلیدها را نمی‌فرستد (کلیدها فقط وقتی اعمال می‌شوند که در ورودی باشند — سازگاری پس‌رو با الگوی `starred` فاز ۳)، و APK جدید فقط بعد از مهاجرت می‌رسد.

## نکته‌های عملیاتی

- **SQLite محلی/توسعه:** نیازی به SQL دستی نیست — `TaskSchema::ensure` در اولین سینک خودش ستون‌ها را اضافه می‌کند (خودش هم تست شده: `tests/phase-trader-test.php` روی دیتابیس تازه بدون ستون‌های نو شروع می‌شود).
- **راستی‌آزمایی بعد از اجرا روی هاست (MySQL):**
  ```sql
  SHOW COLUMNS FROM `tasks` LIKE 'item%';   -- باید دو ردیف: item_type و item_value
  SHOW COLUMNS FROM `lists` LIKE 'pinned';  -- باید یک ردیف
  ```
- **بکاپ/بازیابی اپ:** فیلدهای نو چون بخشی از رکورد کامل کار/لیست‌اند به‌طور خودکار در `karam-backup-*.json` می‌آیند (تست e2e: `tests/e2e-trader.mjs` بلوک ۷) — `BACKUP_VERSION` تغییر نکرده و فایل‌های قدیمی هم بازیابی می‌شوند.
- **کاربران بسته‌ی قدیمی kit-trader:** داده‌شان (لیست‌های «روتین قبل سشن معاملاتی» و «ژورنال معاملات روزانه») لیست/کار عادی سینک‌شده است و با حذف کیت از کاتالوگ **دست نمی‌خورد** — فقط پیشنهادِ فعال‌سازی از UI برداشته شد.
- **تست‌های مرتبط:** `tests/phase-trader-test.php` (۲۵ بررسی — رفت‌وبرگشت، اعتبارسنجی، سازگاری APK قدیمی) · `frontend/tests/trader.test.ts` (۱۶ تست) · `frontend/tests/e2e-trader.mjs` (۴۵ بررسی وب).
