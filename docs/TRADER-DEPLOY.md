# راهنمای انتشار فاز تریدر (چک‌لیست تریدر) — ترتیب قطعی استقرار

> این فایل دستورالعمل قطعی ارتقای هاست از بسته‌ی `karam-host-update-v1.8.1` به نسخه‌ی فعلی با بسته‌ی تجمعی `karam-host-update-v1.9.1.zip` است.
> **ترتیب ۶ گام پایین قطعی است؛ جابه‌جا کردنش باعث از‌دست‌رفتن داده می‌شود** (چرا: بخش «اگر APK قبل از SQL منتشر شود چه می‌شود؟»).
> برای هر گام، «بازگشت (rollback)» هم نوشته شده — قبل از شروع همه را بخوان.

## چه چیزهایی تغییر می‌کند؟ (نسبت به v1.8.1)

| ستون نو | جدول | نوع | معنی |
| --- | --- | --- | --- |
| `item_type` | tasks | VARCHAR(16) NULL | نوع آیتم چک‌لیست: `check`/`num`/`note`/`choice`/`score` — NULL = تیک ساده |
| `item_value` | tasks | VARCHAR(255) NULL | مقدار آیتم (عدد/انتخاب/امتیاز؛ یادداشت کوتاه هم همین‌جاست) |
| `pinned` | lists | TINYINT(1) NOT NULL DEFAULT 0 | لیست پین‌شده — همیشه بالای فهرست |

+ همه‌ی تغییرات P1.3/P1.4 (بکاپ/بازیابی، saveFile) که در بسته‌ی تجمعی هم هستند.
فایل‌های مرتبط: `deploy/upgrade-cumulative-1.8.1-to-1.9.1.sql` (تجمعی تکرارپذیر — همین یکی را اجرا کنید) · `deploy/upgrade-v1.9.sql` و `deploy/upgrade-v1.9.1.sql` (اجزا — برای مرجع) · `deploy/install.sql` و `deploy/install.sqlite.sql` (نصب نو — به‌روز) · `backend/src/Support/TaskSchema.php` (مهاجرت خودکار زمان‌اجرای SQLite/MySQL محلی).

## ترتیب قطعی (۶ گام)

### گام ۰ — پیش‌نیاز
بسته‌ی `karam-host-update-v1.9.1.zip` را دانلود کن و صحتش را چک کن:
```bash
sha256sum -c CHECKSUMS.sha256     # در پوشه‌ی خروجی zip — همه باید OK باشند
```

### گام ۱ — فول‌بک کامل دیتابیس ⚠️ اجباری
```bash
# از ssh (یا phpMyAdmin ← Export ← Quick):
mysqldump -u <DB_USER> -p --single-transaction --default-character-set=utf8mb4 <DB_NAME> > karam-db-backup-$(date +%Y%m%d).sql
```
فایل را جایی خارج از public_html نگه دار.
**بازگشت:** همین فایل لنگر بازگشت کل فرایند است — `mysql -u <DB_USER> -p <DB_NAME> < karam-db-backup-YYYYMMDD.sql` (این یعنی بازگشت به v1.8.1 از هر نقطه‌ای).

### گام ۲ — اجرای SQL تجمعی (قبل از آپلود هر فایلی)
```bash
mysql -u <DB_USER> -p <DB_NAME> < deploy/upgrade-cumulative-1.8.1-to-1.9.1.sql
# یا در phpMyAdmin: تب SQL ← محتوای فایل ← Go
```
- تجمعی = شامل `upgrade-v1.9.sql` (حذف حساب/نگه‌داری) **و** `upgrade-v1.9.1.sql` (ستون‌های تریدر) به ترتیب.
- **تکرارپذیر** است — اگر v1.9 قبلاً اجرا شده، اجرای دوباره بی‌ضرر و بی‌صدا رد می‌شود (گارد INFORMATION_SCHEMA).
**بازگشت:** ترجیحاً فول‌بک گام ۱. بازگشت محدود (فقط ستون‌های تریدر — داده‌ی همین سه ستون پاک می‌شود؛ بقیه‌ی داده سالم می‌ماند):
```sql
ALTER TABLE `tasks` DROP COLUMN `item_type`;
ALTER TABLE `tasks` DROP COLUMN `item_value`;
ALTER TABLE `lists` DROP COLUMN `pinned`;
```
(گسترش enum `purpose` را لازم نیست برگردانید — بی‌ضرر است.)

### گام ۳ — راستی‌آزمایی ستون‌ها (فقط خواندنی)
```sql
SHOW COLUMNS FROM `tasks` LIKE 'item%';
-- باید دقیقاً دو ردیف باشد: item_type (varchar(16), YES) و item_value (varchar(255), YES)
SHOW COLUMNS FROM `lists` LIKE 'pinned';
-- باید دقیقاً یک ردیف باشد: pinned (tinyint(1), NOT NULL, Default 0)
```
اگر هر سه ردیف دیده نشد، به گام ۲ برگرد و ادامه نده.
**بازگشت:** لازم ندارد (فقط خواندنی).

### گام ۴ — آپلود فایل‌ها
اول از وضعیت فعلی هاست نسخه بگیر (از فایل‌منیجر هاست: zip کردن کل public_html یا حداقل `api/` و `panel/` و فایل‌های ریشه) — این لنگر بازگشت فایل‌هاست. بعد:
1. محتوای ریشه‌ی بسته (فایل‌های اپ + `.htaccess` مخفی) → `public_html`
2. محتوای `panel/` → `public_html/panel`
3. محتوای `api/` → `public_html/api` — **فقط `src`، `cron`، `index.php`، `.htaccess` و `storage/.htaccess`؛ پوشه‌های `storage/cache` و `storage/logs` و `storage/backups` و فایل `.env` هاست را دست نزن/جایگزین نکن**
4. یک بار Ctrl+F5 برای کش پنل مرورگر.
**بازگشت:** بسته‌ی zip وضعیت فعلی که در ابتدای همین گام گرفتی را سر جایش استخراج کن (بک‌اند قدیمی با ستون‌های نو هم سازگار است — کلیدهای ناشناخته را نادیده می‌گیرد؛ فقط فیلدهای تریدر را سرو نمی‌کند).

### گام ۵ — تست دودی (قبل از انتشار APK)
1. سلامت سرور:
```bash
curl -s https://app.hojre24shop.ir/api/health
# انتظار: HTTP 200 و "status":"ok" (اگر مشکل باشد 503 با جزئیات می‌آید)
```
2. ورود واقعی: در وب‌اپ با یک حساب موجود وارد شو (تلگرام یا OTP) ← یک کار بساز/تیک بزن ← سینک شود.
3. پنل: `https://app.hojre24shop.ir/panel` ← ورود ادمین ← داشبورد بدون بنر خطا.
**بازگشت:** اگر ورود/سینک شکست خورد → فایل‌های گام ۴ را برگردان (بک‌اند قدیمی با دیتابیس جدید سازگار است) و مشکل را از لاگ `storage/logs` بخوان. اگر دیتابیس مقصر بود → فول‌بک گام ۱.

### گام ۶ — انتشار APK (آخرِ آخر)
APK جدید ساخته‌شده از همین نسخه (versionCode ۱۰ / نسخه ۱.۰.۹ — بیلد بازار: `cd mobile && bun run build:www:bazaar && npx cap sync android`) را در کافه‌بازار بگذار و «دانلود مستقیم» `public_html/karam-latest.apk` را هم به‌روز کن. بعد تست دستگاه: `docs/TRADER-DEVICE-TEST.md`.
**بازگشت:** کافه‌بازار اجازه‌ی بازگردانی نسخه را نمی‌دهد — بازگشت واقعی یعنی انتشار نسخه‌ی بعدی (versionCode ۱۱) ساخته‌شده از کد قبل از فاز تریدر. تاجایی که APK جدید منتشر نشده، «بازگشت» یعنی حذف نسخه‌ی در بازبینی بازار.

## اگر APK قبل از SQL منتشر شود چه می‌شود؟ ⚠️

سرورِ فعلی (بدون ستون‌های نو) کلیدهای `itemType`/`itemValue`/`pinned` را در `normalizeTask/normalizeList` **بی‌صدا نادیده می‌گیرد**. زنجیره‌ی خرابی:
1. APK جدید push می‌زند و مقدار را می‌فرستد → سرور حذفش می‌کند ولی `rev` رکورد بالا می‌رود
2. pull بعدی رکورد را **بدون آن فیلدها** برمی‌گرداند
3. کلاینت کل ردیف محلی را جایگزین می‌کند → **مقدار حتی روی خود دستگاه هم پاک می‌شود**

APKهای قدیمی (که این کلیدها را نمی‌فرستند) بی‌خطرند — الگوی `array_key_exists` فاز ۳. پس: **هرگز APK/وب‌اپ جدید را قبل از گام ۲ منتشر نکن.** وب‌اپِ داخل همین بسته هم مشمول همین قاعده است (بعد از SQL آپلود شود).

## نکته‌های عملیاتی

- **SQLite محلی/توسعه:** نیازی به SQL دستی نیست — `TaskSchema::ensure` در اولین سینک خودش ستون‌ها را اضافه می‌کند (خودش هم تست شده: `tests/phase-trader-test.php` روی دیتابیس تازه بدون ستون‌های نو شروع می‌شود).
- **بکاپ/بازیابی اپ:** فیلدهای نو چون بخشی از رکورد کامل کار/لیست‌اند به‌طور خودکار در `karam-backup-*.json` می‌آیند — `BACKUP_VERSION` تغییر نکرده و فایل‌های قدیمی هم بازیابی می‌شوند.
- **کاربران بسته‌ی قدیمی kit-trader:** داده‌شان (لیست‌های «روتین قبل سشن معاملاتی» و «ژورنال معاملات روزانه») لیست/کار عادی سینک‌شده است و با حذف کیت از کاتالوگ **دست نمی‌خورد** — فقط پیشنهادِ فعال‌سازی از UI برداشته شد.
- **تست‌های مرتبط:** `tests/phase-trader-test.php` (۲۵ بررسی — رفت‌وبرگشت، اعتبارسنجی، سازگاری APK قدیمی) · `frontend/tests/trader.test.ts` (۱۶ تست) · `frontend/tests/e2e-trader.mjs` (۴۵ بررسی وب) · تست دستی دستگاه: `docs/TRADER-DEVICE-TEST.md`.
