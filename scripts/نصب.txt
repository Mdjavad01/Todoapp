پک v22 — کارام
════════════════════════════════════════════

این پک شامل گام ۲ (کلید خاموش‌کردن پرداخت‌ها) است.
همچنین همه‌ی فیکس‌های امنیتی گام ۱ (پک v21) و قابلیت‌های قبلی داخلش هست —
اگر v21 را نصب نکرده‌اید، همین پک کافی است.

──────────────────────────────────────────────
الف) نصب (سه پوشه — مثل همیشه)
──────────────────────────────────────────────
۱) فایل zip را باز کنید؛ سه پوشه می‌بینید: (اپ) · panel · api

۲) محتوای پوشه‌ی اصلی (اپ) → public_html
   (فایل .htaccess مخفی هم باید آپلود شود)

۳) محتوای panel → public_html/panel

۴) محتوای api → public_html/api
   (پوشه‌های storage را جایگزین نکنید؛ فقط src و cron و index.php و .htaccess)

۵) کش پنل مرورگر: یک بار Ctrl+F5

──────────────────────────────────────────────
ب) مهاجرت دیتابیس (اختیاری)
──────────────────────────────────────────────
phpMyAdmin ← دیتابیس کارام ← SQL ← محتوای deploy/upgrade-v1.4.sql ← Go
(فقط سید ۴ کلید جدید؛ تکرارپذیر. بدون اجرا هم همه‌چیز با پیش‌فرض «روشن» کار می‌کند)

──────────────────────────────────────────────
ج) قابلیت جدید: کلید خاموش‌کردن پرداخت‌ها
──────────────────────────────────────────────
پنل ← تنظیمات ← گروه اول «کلید اصلی پرداخت (توقف اضطراری فروش) — گام ۲»:

  • کلید اصلی: با بستنش شروع همه‌ی پرداخت‌های جدید در وب و اندروید همان
    لحظه سمت سرور بسته می‌شود (سفارش‌های در جریان و پروِ فعلی‌ها سالم می‌مانند؛
    کدهای هدیه معتبر می‌مانند). خاموش‌کردن دیالوگ تأیید دارد و در Audit ثبت می‌شود.
  • سوییچ وب و سوییچ اندروید: مستقل — مثلاً قبل از بازبینی بازار فقط اندروید را ببندید.
  • پیام نمایشی: وقتی پرداخت بسته است در اپ (کارت کهربایی صفحه‌ی پرو) دیده می‌شود.
  • داشبورد پنل: وقتی هر پلتفرمی بسته باشد بنر زرد وضعیت نشان می‌دهد.

منطق سمت سرور است (PaymentsPolicy) — حتی اگر اپ قدیمی باشد، پرداختِ بسته با
۴۰۳ code=payments_disabled رد می‌شود.

APK همگام (نسخه ۱.۰.۲ — کد ۳):
  باندل داخل APK با همین پک به‌روز شده (وضعیت کلید + مخفی‌شدن UI پرداخت).
  از داشبورد (karam-latest.apk) دانلود و جایگزین فایل قبلی در public_html کنید؛
  سپس پنل ← تنظیمات ← app_latest_version = 1.0.2

بیلد بدون پرداخت برای بازار — حالا خودکار در بیلد ابری:
  هر اجرای Actions دو APK می‌سازد: karam-latest.apk (پیش‌فرض — سایت/به‌روزرسانی)
  و karam-bazaar.apk (BUILD_MODE=bazaar → VITE_PAYMENTS_BUILD=off — کل UI پرداخت
  از باندل حذف). برای بازار فقط karam-bazaar.apk را در پنل بازار آپلود کنید؛
  app_update_url هم فقط به karam-latest.apk اشاره می‌کند.
  بیلد دستی محلی: cd mobile && bun run build:www:bazaar

کلید مستقل کد هدیه (gift_codes_enabled — نام جدید gift_enabled قبلی):
  پنل ← تنظیمات ← گروه «کلید اصلی پرداخت» ← سوییچ «کد هدیه فعال (مستقل از پرداخت)»
  • خاموش = هیچ کدی استعلام/مصرف/ثبت نمی‌شود (حتی کدهای فعال)
  • از کلید اصلی پرداخت کاملاً مستقل است (خاموشی پرداخت روی کد هدیه اثر ندارد)
  • تغییر نام در اولین استعلام کد هدیه خودکار است؛ مهاجرت صریح: deploy/upgrade-v1.5.sql

──────────────────────────────────────────────
د) تست‌های پیشنهادی (۶ مورد)
──────────────────────────────────────────────
۱) پنل ← تنظیمات ← کلید اصلی را ببندید → در اپ (وب و اندروید) صفحه‌ی پرو
   فقط کارت پیام + فیلد کد هدیه نشان بدهد و دکمه‌ی خرید مخفی شود
۲) با کلید بسته، داشبورد پنل بنر زرد «کلید پرداخت‌ها بسته است» را نشان بدهد
۳) کلید را دوباره روشن کنید → UI خرید برمی‌گردد (کش اپ با یک بستن/بازکردن تازه می‌شود)
۴) سوییچ «پرداخت در وب» را ببندید → در وب پیام بسته؛ در اپ اندروید خرید عادی (برعکسش هم درست)
۵) سوییچ «کد هدیه فعال (مستقل از پرداخت)» را خاموش کنید → استعلام کد در اپ پیام
   «کد هدیه فعلاً غیرفعال است» بدهد؛ با کلید اصلیِ بسته هم کد هدیه همچنان کار می‌کند
۶) یک پرداخت آزمایشی با کد هدیه → تخفیف زنده مثل قبل؛ و ورود/سینک/OTP دست‌نخورده

قابلیت‌های قبلی (پک v21 — خلاصه): فیکس‌های امنیتی گام ۱ (حذف diag، شورتکد
ورود مالک از تنظیمات، تأیید مبلغ fail-closed زیبال، اندروید سخت‌گیرانه،
OTP_DEBUG در production) + لوگوی رسمی جدید و APK ۱.۰.۱ — راهنمای کامل در
docs/INSTALL.md (بخش ۱۱ و ۱۶ و ۱۷) موجود است.
