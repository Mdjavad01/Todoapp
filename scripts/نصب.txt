پک کارام v1.12.2 — بهداشت مخزن + اصلاح مستندات (بدون SQL)
════════════════════════════════════════════════════════════════════════

این پک، ارتقای تجمعی از هر وضعیتی ≥ v1.7 به v1.12.2 است.
⚠️ این نسخه هیچ مهاجرت SQL ندارد — اگر هاست شما هنوز روی v1.10.1 یا قدیمی‌تر
است، همین پک + یک‌بار اجرای SQL تجمعی (توضیح بخش الف) شما را کامل می‌کند.

⚠️ پوشه‌ی deploy-sql/ داخل پک فقط برای مرجع (phpMyAdmin) است؛ روی هاست آپلود
نشود. داخل خودش htaccess سد کامل دارد — حتی اگر اشتباهاً آپلود شود از وب
قابل دسترسی نیست، ولی لزومی به حضورش روی هاست نیست.

چی در v1.12.1 و v1.12.2 نو است (اصلاحیه‌ی صداقت بازار + بهداشت مخزن):
  ۰) v1.12.1 — صداقت باندل بازار: هیچ متن «پرو/خرید/ارتقا/درگاه/کارت‌به‌کارت» در APK
     بازار نیست (alias فیزیکی ماژول در vite.config.ts + تبدیل صفحات ایستا با
     bazaar-static-pages.mjs) + گام نو CI «اسکن صداقت باندل بازار» + رفع شکست
     پنهان گام تست PHP (حذف continue-on-error)
  ۰۰) v1.12.2 — هیچ فایل اجرایی هاست تغییر نکرده؛ فقط بهداشت مخزن: حذف APKهای
     کهنه از گیت (pack-work) + گام نو CI «منع APK/AAB در مخزن» + اصلاح توضیح
     مکانیزم در CHANGELOG/BAZAAR-LISTING — فایل ارسالی به بازار فقط آرتیفکت CI
     با نام karam-bazaar-apk است، نه هیچ فایل داخل ریپو

چی در v1.12.0 نو است (موج ممیزی پیش از کافه‌بازار):
  ۱) htaccess واحد روت — فایل کش اپ (frontend/public/.htaccess) حذف و با
     deploy/.htaccess ترکیب شد: HTTPS اجباری + CSP سخت‌گیرانه + nosniff/
     Referrer/Permissions-Policy + سد diag/install/.sql/.env + کش یک‌ساله‌ی
     immutable + فشرده‌سازی — همه در یک فایل واحد
  ۲) HSTS آغازین ملایم: max-age=300 (۵ دقیقه، بدون includeSubDomains/preload)
     ⚠️ بعد از چند روز تأیید سالم همه‌چیز، مقدار را در .htaccess روت به
     "max-age=31536000; includeSubDomains" افزایش دهید (بخش ج)
  ۳) صفحات /privacy/ و /terms/ استایلشان به فایل خارجی (style.css) منتقل شد —
     با CSP سخت‌گیرانه سازگار است (بدون unsafe-inline)
  ۴) امنیت OTP: ژورنال دیسکی کدهای ورود (issued-otp.jsonl) به‌طور کامل حذف شد —
     کد خام هرگز روی دیسک نوشته نمی‌شود (فقط hash در دیتابیس + خود کد در کانال
     کاربر). در پنل، شورتکد تلگرام دیگر کد را نشان نمی‌دهد؛ کد در چت تلگرام
     کاربر است. شورتکد ایمیل/پیامک بدون تغییر است (کد در پاسخ ادمین می‌آید)
  ۵) بکاپ و یادآور تلگرامی: هر دو پیش‌فرض خاموش‌اند (کلید پنل) و بند صریح
     «چه داده‌ای، به کجا، رمزگذاری‌نشده» به حریم خصوصی/قوانین (وب + درون‌اپ) اضافه شد
  ۶) اشتراک فایل در اپ اندروید فقط از زیرمسیر اختصاصی cache/karam-share/ —
     کل حافظه‌ی خارجی و کل cache دیگر در معرض FileProvider نیست
  ۷) کلیدهای صفحه‌ی وضعیت کرون‌ها از .env قابل تغییرند: BACKUP_CHECK_KEY،
     RETENTION_CHECK_KEY، TELEGRAM_POLL_CHECK_KEY، REMINDER_CHECK_KEY
     (خالی = پیش‌فرض قبلی — بدون تغییر .env همه‌چیز مثل قبل کار می‌کند)
  ۸) مسیر مطلق سرور (__FILE__) از صفحه‌های وضعیت کرون حذف شد
  ۹) لیستینگ کافه‌بازار صادق شد (بدون وعده‌ی پرداخت/پرو/۷روز) + درصد تخفیف
     واقعی «حدود ۶۸٪» در seed پلن سالانه و لندینگ
  ۱۰) CI: هر بیلد APK حالا اول تست‌های فرانت را اجرا می‌کند — شکست تست =
      شکست بیلد و هیچ APK ای صادر نمی‌شود
  ۱۱) seed نصب تازه: trial_enabled=1 (دوره آزمایشی ۷روزه برای حساب‌های نو)

پیش از ارسال فرم کافه‌بازار:
  □ در phpMyAdmin چک کنید: SELECT value FROM settings WHERE `key`='trial_enabled';
    اگر «0» بود → 1 بگذارید (پنل ← تنظیمات هم قابل تغییر است)
  □ فایل‌های قدیمی ژورنال OTP روی هاست پاک شوند (بخش ج — گام ۴)
  □ karam-bazaar.apk نوِ این موج را آپلود کنید (M-01 داخلش است)

الف) مهاجرت دیتابیس — فقط برای هاست‌های زیر v1.10.1
──────────────────────────────────────────────
اگر آخرین SQL اجراشده روی هاست قدیمی‌تر از بخش ۵ است، فایل
deploy-sql/upgrade-cumulative-1.7-to-1.10.1.sql را در phpMyAdmin اجرا کنید
(یک فایل، پنج بخش، تکرارپذیر):

  بخش ۱ — v1.8: واحد پول سرور ریال → تومان صحیح (÷۱۰) + جدول‌های پشتیبان
          (_bak_v18_*). فقط وقتی ستون‌های ریالی موجود باشند تبدیل می‌کند.
  بخش ۲ — v1.9: بسته‌ی ایمنی و اعتماد (enum account_delete + کلیدهای نگه‌داری)
  بخش ۳ — v1.9.1: فاز تریدر (tasks.item_type / item_value + lists.pinned)
  بخش ۴ — v1.10: lists.template_key + بک‌فیل نامی ۵ لیست تریدر (trader.0..4)
  بخش ۵ — v1.10.1: ایندکس lists از یونیکِ سراسری uuid به یونیکِ به‌ازای هر
          کاربر (user_id, uuid) — عامل ۱۰۶۲/۵۰۰ لیست پیش‌فرض کاربران بعدی.
          هیچ ردیفی حذف یا تغییر نمی‌کند؛ فقط ایندکس عوض می‌شود.

هاست شما اگر v1.10.1 به بعد است — این بخش را کلاً رد کنید و مستقیم بروید گام ب.

راستی‌آزمایی (فقط وقتی بخش الف را اجرا کردید):
  SHOW INDEX FROM `lists` WHERE Key_name='uq_lists_user_uuid';  →  دو ردیف

     ← Content-Security-Policy: default-src 'self' ...
     ← Strict-Transport-Security: max-age=300
     ← X-Content-Type-Options: nosniff
   curl -sI https://app.hojre24shop.ir/assets/$(ls نام‌فایل-hash-دار.js) | grep -i cache
     ← Cache-Control: public, max-age=31536000, immutable

     ← Cache-Control: no-cache, must-revalidate
۲) سدها:

     ← 404 (بدون کلید)
   curl -s -o /dev/null -w "%{http_code}\n" https://app.hojre24shop.ir/deploy-sql/install.sql
     ← 403 یا 404 (اگر آپلودش کرده باشید)
   curl -s -o /dev/null -w "%{http_code}\n" https://app.hojre24shop.ir/backup-db.php
     ← 404/403 (diag/install هم بسته‌اند)
۳) مرورگر: اپ وب باز شود؛ DevTools ← Console ← هیچ خطای CSP نباشد (مخصوصاً

   (اگر بی‌استایل‌اند = style.css آپلود نشده)
۴) پاک‌سازی فایل‌های ژورنال OTP قدیمی (یک‌بار برای همیشه — M-06):
   File Manager → api/storage/cache/ → فایل issued-otp.jsonl را حذف کنید
   (اگر هست). از این به بعد هیچ‌وقت ساخته نمی‌شود.
۵) تست دودی کارکردی: /api/health → ok؛ ورود با کد ایمیل؛ سینک یک کار؛
   پنل ← شورتکد ایمیل → کد در پاسخ می‌آید (مثل قبل)
۶) بعد از چند روز سالم‌بودن همه‌چیز: در .htaccess روت هاست مقدار HSTS را از
