# کارام — بسته‌ی هاست v1.9.1 (تجمعی از v1.8.1)

> این بسته ارتقای **تجمعی** از `karam-host-update-v1.8.1` تا امروز است — همه‌ی تغییرات P1.2/P1.3/P1.4 و «فاز تریدر» داخلش هست. نیازی به هیچ پک واسط نیست.
> **ترتیب ۶ گام را جابه‌جا نکنید.** برای هر گام «بازگشت (rollback)» نوشته شده.

---

## محتوای بسته

| پوشه/فایل | چیست | وضعیت نسبت به v1.8.1 |
| --- | --- | --- |
| ریشه (فایل‌های اپ + `.htaccess` مخفی) | وب‌اپ — بیلد تازه | **تغییر** — فاز تریدر + بکاپ/بازیابی جدید (P1.3/P1.4) |
| `panel/` | پنل ادمین | بدون تغییر (بازآپلود بی‌ضرر) |
| `api/` | بک‌اند PHP (`src` + `cron` + `index.php` + `.htaccess` + `storage/.htaccess`) | **تغییر** — پشتیبانی فیلدهای تریدر + سخت‌گیری بکاپ |
| `deploy/upgrade-cumulative-1.8.1-to-1.9.1.sql` | **مهاجرت تجمعی — همین یکی اجرا می‌شود** | نو |
| `deploy/upgrade-v1.9.sql` و `deploy/upgrade-v1.9.1.sql` | دو جزءِ تجمعی (برای مرجع) | v1.9 قبلاً اجرا شده / v1.9.1 نو |
| `CHECKSUMS.sha256` | صحت فایل‌ها | نو |

هیچ رازی (`.env`، کلید، رمز DB، توکن) داخل بسته نیست — `.env` هاست دست‌نخورده می‌ماند.

## گام ۰ — صحت بسته
```bash
sha256sum -c CHECKSUMS.sha256        # همه باید OK باشند
```
**بازگشت:** ندارد (فقط خواندنی).

## گام ۱ — فول‌بک کامل دیتابیس ⚠️ اجباری
```bash
mysqldump -u <DB_USER> -p --single-transaction --default-character-set=utf8mb4 <DB_NAME> > karam-db-backup-$(date +%Y%m%d).sql
```
(یا phpMyAdmin ← Export ← Quick). فایل را **خارج از public_html** نگه دارید.
**بازگشت:** همین فایل لنگر بازگشت کل فرایند است: `mysql -u <DB_USER> -p <DB_NAME> < karam-db-backup-YYYYMMDD.sql`

## گام ۲ — اجرای SQL تجمعی (قبل از هر آپلودی)
```bash
mysql -u <DB_USER> -p <DB_NAME> < deploy/upgrade-cumulative-1.8.1-to-1.9.1.sql
```
(یا phpMyAdmin ← تب SQL ← محتوا ← Go). تکرارپذیر است — اگر v1.9 قبلاً اجرا شده، بخش ۱ بی‌صدا رد می‌شود و فقط ستون‌های تریدر (v1.9.1) اعمال می‌شود.
**بازگشت:** ترجیحاً فول‌بک گام ۱. بازگشت محدود (فقط ستون‌های تریدر — داده‌ی همین سه ستون از بین می‌رود):
```sql
ALTER TABLE `tasks` DROP COLUMN `item_type`;
ALTER TABLE `tasks` DROP COLUMN `item_value`;
ALTER TABLE `lists` DROP COLUMN `pinned`;
```

## گام ۳ — راستی‌آزمایی ستون‌ها
```sql
SHOW COLUMNS FROM `tasks` LIKE 'item%';   -- باید دو ردیف: item_type (varchar(16)) و item_value (varchar(255))
SHOW COLUMNS FROM `lists` LIKE 'pinned';  -- باید یک ردیف: pinned (tinyint(1) Default 0)
```
اگر هر سه دیده نشد، ادامه ندهید — به گام ۲ برگردید.
**بازگشت:** ندارد (فقط خواندنی).

## گام ۴ — آپلود فایل‌ها
اول از وضعیت فعلی هاست نسخه بگیرید (فایل‌منیجر ← zip کل public_html یا حداقل `api/` و ریشه) — لنگر بازگشت فایل‌ها. بعد:
1. محتوای **ریشه‌ی** بسته → `public_html` (فایل مخفی `.htaccess` هم باید آپلود شود)
2. محتوای `panel/` → `public_html/panel`
3. محتوای `api/` → `public_html/api` — **فقط `src`، `cron`، `index.php`، `.htaccess` و `storage/.htaccess`. پوشه‌های `storage/cache` و `storage/logs` و `storage/backups` و فایل `.env` هاست را جایگزین نکنید**
4. یک بار Ctrl+F5 (کش پنل مرورگر)
**بازگشت:** zip وضعیتِ ابتدای همین گام را سر جایش استخراج کنید (بک‌اند قدیمی با دیتابیس جدید سازگار است — کلیدهای ناشناخته را نادیده می‌گیرد).

## گام ۵ — تست دودی
```bash
curl -s https://app.hojre24shop.ir/api/health
# انتظار: HTTP 200 و "status":"ok" (مشکل = 503 با جزئیات)
```
+ ورود واقعی در وب‌اپ (OTP/تلگرام) ← ساخت/تیک یک کار ← سینک.
+ ورود ادمین به `/panel` ← داشبورد بدون بنر خطا.
**بازگشت:** شکست → فایل‌های گام ۴ را برگردانید و لاگ `storage/logs` را بخوانید؛ مقصر دیتابیس بود → فول‌بک گام ۱.

## گام ۶ — انتشار APK (آخرِ آخر)
APK جدید از همین نسخه (versionCode ۱۰ / نسخه ۱.۰.۹، بیلد بازار) را در کافه‌بازار بگذارید و `public_html/karam-latest.apk` را به‌روز کنید. بعد تست دستگاه: `docs/TRADER-DEVICE-TEST.md`.
**بازگشت:** بازار بازگردانی نسخه ندارد — بازگشت واقعی = انتشار versionCode ۱۱ از کد قبل از فاز تریدر.

---

## ⚠️ اگر APK/وب‌اپ جدید قبل از SQL منتشر شود چه می‌شود؟

سرور فعلی (بدون ستون‌های نو) کلیدهای `itemType`/`itemValue`/`pinned` را **بی‌صدا نادیده می‌گیرد**: push مقدار → سرور حذفش می‌کند و `rev` بالا می‌رود → pull رکورد را بدون فیلد برمی‌گرداند → کلاینت ردیف محلی را جایگزین می‌کند → **مقدار حتی روی خود دستگاه پاک می‌شود**. APKهای قدیمی بی‌خطرند. پس: اول SQL (گام ۲)، بعد فایل‌ها (گام ۴)، آخر APK (گام ۶).

## نکته‌ها
- SQLite محلی/توسعه‌ای نیازی به SQL ندارد — `TaskSchema::ensure` اولین سینک خودش ستون‌ها را می‌سازد.
- بکاپ/بازیابی اپ فیلدهای نو را خودکار حمل می‌کند (`BACKUP_VERSION` همان ۱ — فایل‌های قدیمی هم بازیابی می‌شوند).
- دارایی‌های قدیمی وب (فایل‌های hash-دار قبلی) روی هاست می‌مانند ولی بی‌ضررند؛ اگر خواستید بعد از گام ۵ پاکشان کنید.
- جزئیات کامل: `docs/TRADER-DEPLOY.md` در مخزن.
