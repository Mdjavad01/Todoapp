> این بسته **پک استقرار کامل** است (همان محتوای v1.10.0 + فیکس‌های v1.10.1) و از هر وضعیتی ≥ v1.7 یکجا به v1.10.1 می‌رساند.
> عامل «خطای داخلی سرور» سینک با عیب‌یاب روی هاست واقعی پیدا شد: **یونیکِ سراسری `uq_lists_uuid`** — push لیست پیش‌فرضِ هر کاربرِ دوم با 1062 می‌شکست. این بسته: (۱) مهاجرت SQL ایندکس، (۲) فیکس چهار کوئریِ پارامتر تکراری (HY093 فعال‌سازی دوره آزمایشی در لاگ شما)، (۳) گارد تمیز 1062 در سینک.
> **ترتیب گام‌ها را جابه‌جا نکنید.** برای هر گام «بازگشت» نوشته شده.

## گام ۲ — اجرای SQL (قبل از هر آپلودی)
**هاست شما الان دقیقاً روی v1.10 است** (عیب‌یاب تأیید کرد: تومان ✅ اعتماد ✅ تریدر ✅ کلید قالب ✅) — پس هر دو فایل جواب می‌دهد و فقط بخش ۵ اعمال می‌شود:
- **پیش‌فرض:** `deploy/upgrade-cumulative-1.7-to-1.10.1.sql` (تجمعی — از هر وضعیتی ≥ v1.7)
- یا فقط بخش ۵: `deploy/upgrade-v1.10.1.sql`

```bash
mysql -u <DB_USER> -p <DB_NAME> < deploy/upgrade-cumulative-1.7-to-1.10.1.sql
```
(یا phpMyAdmin ← تب SQL ← محتوا ← Go). بخش‌های ۱ تا ۴ قبلاً اجرا شده‌اند و خودشان رد می‌شوند؛ بخش ۵ ایندکس lists را از یونیکِ سراسری به یونیکِ به‌ازای هر کاربر عوض می‌کند — **هیچ ردیفی حذف یا تغییر نمی‌کند.**
**بازگشت:**
```sql
ALTER TABLE `lists` DROP INDEX `uq_lists_user_uuid`, ADD UNIQUE KEY `uq_lists_uuid` (`uuid`);
```
(فقط اگر مطمئنید دو کاربر هم‌uuid ندارند — وگرنه فول‌بک گام ۱.)

## نکته‌ها
- عیب‌یاب سه باگ را نشان داد که هر سه در همین بسته رفع شده‌اند:
  1. **۱۰۶۲ لیست پیش‌فرض** (ریشه‌ی 500 سینک) → بخش ۵ SQL + گارد `SyncService`
  2. **HY093 دوره آزمایشی** (لاگ: کاربران ۱۱ و ۱۲) → فیکس کوئری `activateTrial` — توجه: دوره آزمایشی آن دو کاربر فعال نشده؛ از پنل دستی پرو بدهید یا دوباره ثبت‌نام‌شان کنید
  3. **«مهاجرت اسکیمای اطلاعیه‌ها ناموفق: near '?'»** (هر فراخوانی اطلاعیه/تنظیمات در لاگ) → این فیکس از v1.10.0 در مخزن بود ولی api قدیمی روی هاست بود؛ با آپلود همین بسته لاگ تمیز می‌شود
- SQLite محلی: فایل `karam-dev.sqlite3` را یک بار پاک کنید تا اسکیمای نو (یونیک به‌ازای هر کاربر) ساخته شود — داده‌ی تست است.
- هیچ عدد قیمت، versionCode، APP_VERSION یا BACKUP_VERSION در این نسخه تغییر نکرده است.
