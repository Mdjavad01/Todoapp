# کارام — بسته‌ی هاست v1.10 (تجمعی از v1.7 — و از v1.8.1 هم)

> این بسته ارتقای **تجمعی** از هر وضعیتی است که آخرین SQL اجراشده‌اش `upgrade-v1.7.sql` یا جدیدتر باشد — یعنی اگر آخرین پکی که روی هاست نصب کرده‌اید «پک کارام v1.7.0» (یا هر پک بعدی مثل v1.4.0/v1.5.0/v1.8.1) بوده، همین بسته کافی است. همه‌ی تغییرات بین v1.7 تا امروز داخلش هست: مهاجرت تومان (v1.8)، بسته‌ی ایمنی و اعتماد (v1.9)، فاز تریدر (v1.9.1) و «P2.0 بازطراحی بسته‌های شغلی + بستن بدهی templateKey» (v1.10).
> **ترتیب ۶ گام را جابه‌جا نکنید.** برای هر گام «بازگشت (rollback)» نوشته شده.
> ممیزی و تصمیم‌های این نسخه: `docs/P2-JOB-PACKS-AUDIT.md` — چک‌لیست دستگاه: `docs/P2-JOB-PACKS-DEVICE-TEST.md`.

## گام ۱ — فول‌بک کامل دیتابیس ⚠️ اجباری

mysqldump -u <DB_USER> -p --single-transaction --default-character-set=utf8mb4 <DB_NAME> > karam-db-backup-$(date +%Y%m%d).sql

## گام ۲ — اجرای SQL تجمعی (قبل از هر آپلودی)
**کدام فایل؟**
- **پیش‌فرض (همیشه درست):** `deploy/upgrade-cumulative-1.7-to-1.10.sql` — چهار بخش: تومان (v1.8) + اعتماد (v1.9) + تریدر (v1.9.1) + کلید قالب (v1.10). از هر وضعیتی ≥ v1.7 جواب می‌دهد.
- جایگزین: `upgrade-cumulative-1.8.1-to-1.10.sql` — فقط اگر مطمئنید پک v1.8.1 را کامل (فایل + هر دو SQL) اجرا کرده‌اید.
- شک دارید؟ همان پیش‌فرض را اجرا کنید — همه‌ی بخش‌ها گارد دارند و اجرای دوباره بی‌ضرر است؛ هیچ عددی دوبرابر نمی‌شود.

```bash
mysql -u <DB_USER> -p <DB_NAME> < deploy/upgrade-cumulative-1.7-to-1.10.sql
```
(یا phpMyAdmin ← تب SQL ← محتوا ← Go). بخش ۱ مبلغ‌ها را ÷۱۰ تومان می‌کند (فقط وقتی ستون‌های ریالی موجود باشند) و جدول‌های پشتیبان `_bak_v18_*` می‌سازد؛ بخش‌های بعدی ستون‌های نو را می‌سازند و بخش ۴ پنج لیست تریدرِ موجود را با تطبیق نام کلید می‌دهد (`trader.0..4`).
**بازگشت:** ترجیحاً فول‌بک گام ۱. بازگشت محدود (فقط ستون P2.0 — کلیدهای قالبی از بین می‌روند و اپ به تشخیص نامیِ قدیمی برمی‌گردد):
```sql
ALTER TABLE `lists` DROP COLUMN `template_key`;
```

## گام ۳ — راستی‌آزمایی ستون‌ها
```sql
SHOW COLUMNS FROM `tasks` LIKE 'item%';       -- دو ردیف: item_type و item_value (از v1.9.1)
SHOW COLUMNS FROM `lists` LIKE 'pinned';      -- یک ردیف: pinned (از v1.9.1)
SHOW COLUMNS FROM `lists` LIKE 'template_key';-- یک ردیف: template_key (varchar(32), NULL) — نو
SELECT name, template_key FROM `lists` WHERE name IN ('قوانین من','پیش از بازار','قبل از معامله','بعد از بازار','ریویو هفتگی') AND deleted_at IS NULL;
-- انتظار: هر ۵ ردیف با کلید trader.0 تا trader.4 (بک‌فیل)
```
اگر ستون سوم دیده نشد، ادامه ندهید — به گام ۲ برگردید.
**بازگشت:** ندارد (فقط خواندنی).

## گام ۴ — آپلود فایل‌ها
اول از وضعیت فعلی هاست نسخه بگیرید (فایل‌منیجر ← zip کل public_html یا حداقل `api/` و ریشه) — لنگر بازگشت فایل‌ها. بعد:
1. محتوای **ریشه‌ی** بسته → `public_html` (فایل مخفی `.htaccess` هم باید آپلود شود)
2. محتوای `panel/` → `public_html/panel`
3. محتوای `api/` → `public_html/api` — **فقط `src`، `cron`، `index.php`، `.htaccess` و `storage/.htaccess`. پوشه‌های `storage/cache` و `storage/logs` و `storage/backups` و فایل `.env` هاست را جایگزین نکنید**
4. یک بار Ctrl+F5 (کش پنل مرورگر)
**بازگشت:** zip وضعیتِ ابتدای همین گام را سر جایش استخراج کنید (بک‌اند قدیمی با دیتابیس جدید سازگار است — کلید ناشناخته‌ی `templateKey` را نادیده می‌گیرد).

## ⚠️ اگر APK/وب‌اپ جدید قبل از SQL منتشر شود چه می‌شود؟

سرور فعلی (بدون ستون نو) کلید `templateKey` را **بی‌صدا نادیده می‌گیرد**: push کلید → سرور حذفش می‌کند و `rev` بالا می‌رود → pull رکورد را بدون کلید برمی‌گرداند → کلاینت ردیف محلی را جایگزین می‌کند → **کلید حتی روی خود دستگاه پاک می‌شود** و اپ به تشخیص نامی برمی‌گردد (کارکرد عادی، ولی مزیت «تغییر نام = بدون تکرار» از دست می‌رود). APKهای قدیمی کاملاً بی‌خطرند. پس: اول SQL (گام ۲)، بعد فایل‌ها (گام ۴)، آخر APK (گام ۶).

## نکته‌ها
- SQLite محلی/توسعه‌ای نیازی به SQL ندارد — `ListSchema::ensure` اولین سینک خودش ستون را می‌سازد و بک‌فیل تریدر را هم انجام می‌دهد.
- بکاپ/بازیابی اپ کلید قالبی را خودکار حمل می‌کند (`BACKUP_VERSION` همان ۱ — فایل‌های قدیمی هم بازیابی می‌شوند).
- کاربران kit های قدیمی v16 هیچ تغییری در داده‌شان نمی‌بینند — لیست‌هایشان عادی می‌ماند و با بسته‌های نو ادغام نمی‌شود.
- در بیلد بازار هیچ مسیر خریدی نیست (Poolakey = فاز بعدی P2.1)؛ بسته‌ها فقط با حساب پرو (اشتراک/کد هدیه/رفرال/آزمایشی) فعال می‌شوند.
- جزئیات کامل: `docs/P2-JOB-PACKS-AUDIT.md` و `CHANGELOG.md` در مخزن.
